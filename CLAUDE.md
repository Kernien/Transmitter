# Transmitter: правила проекта

Flutter-приложение (Android, Windows, Web) для передачи постов между
устройствами через облако пользователя со сквозным шифрованием.
Описание для пользователей — README.md; архитектура, сборка, выпуск релизов
и план — docs/DEVELOPMENT.md.

- Общение и комментарии в коде на русском.
- Тексты интерфейса — только в lib/l10n/app_en.arb и app_ru.arb (оба файла,
  тест l10n_test проверяет совпадение ключей). В core нет пользовательских
  текстов: ошибки несут ErrorCode, текст даёт `describeError` (app/l10n.dart).
- Лицензия GPL-3.0 (LICENSE). Коммиты — с адресом 101323434+Kernien@users.noreply.github.com (уже в git config репозитория), личную почту в историю не добавлять.
- Слои: `features → app → data → core/domain`. Импорт «вверх» запрещён.
- Конкретные реализации создаются только в `lib/main.dart`; остальной код
  получает зависимости через конструктор и работает с интерфейсами.
- Новое облако: `core/storage/providers/<name>_storage.dart` +
  `<name>_adapter.dart` и регистрация в `main.dart`. Существующие модули не трогать.
- Формат ключа (`TRM1.`, поля s/p/n/m; m — лимит файла, у старых ключей его нет → 25 МБ), HKDF info-строки, `CloudProviderId.code` и раскладка
  файлов в облаке уже используются в данных пользователей. Менять их только с
  новой версией формата и обратной совместимостью.
- Адреса возврата OAuth прописаны в консолях облаков: порт 47819 (Windows),
  схема `app.transmitter://oauth/<облако>` (Android), `auth.html` и порт 47820
  (веб). Не менять без обновления README и консолей.
- В вебе вход в облако должен начинаться синхронно из обработчика нажатия
  (без `await` до `window.open`), иначе браузер заблокирует окно.
- Любое изменение логики сопровождается тестом. Перед завершением задачи
  `flutter analyze` и `flutter test` должны проходить без ошибок.
- Flutter SDK: `C:\dev\flutter`; JAVA_HOME — JBR из Android Studio.
